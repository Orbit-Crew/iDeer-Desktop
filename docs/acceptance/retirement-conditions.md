## 三条件定义（摘自 #131 正文）

| # | 条件 | #131 依据（要旨） |
| --- | --- | --- |
| ① | **Win7 全量验收通过** | 最终候选在真实 Win7 完成核心清单与全部声明能力专项（T131-02…06）；兼容问题修复并复验；没有阻断替代使用的未解决问题；缺环境/软件/许可/凭据或必需项失败、未执行、不完整时不通过 |
| ② | **存量用户逐一确认** | 每位存量用户迁移完成或明确不再使用；旧数据保留和查阅方式已告知；不设虚构固定等待天数；失联用户不得默认视作同意 |
| ③ | **维护者明确确认** | 停止有限维护与归档须维护者明确确认（记录确认人与执行结果）；确认前不执行实际归档或删除；保留来源、兼容补丁/工具仓维护、暂缓能力与后续责任 |

## 与 #131 验收操作的衔接

- **T131-01（追溯矩阵）**：本矩阵是其行来源——48 行与 #70 子票经 #89 台账锁步，
  每行两系统各格均登记执行入口（automated/command/scenario/manual 四类）。
- **T131-06（全部声明能力复验，留能力矩阵）**：矩阵 win7 列即该要求登记的"能力矩阵"；
  每个能力行默认携带 `T131-06` 场景锚点，安装/文件审批/浏览器配对/进程生命周期类行
  另行映射 T131-02…05 与 desktop W7-01…08（docs/validation.md）。
- **场景状态落格**：#131 逐场景 passed / failed / unexecuted / incomplete 在证据文件内
  逐场景记录；落格规则见矩阵框架文档的状态对照表（failed 场景使格子止步于
  `部分验收` 或更低，永不翻 `已验收`）。

## 规则重申（引用 #131/validation.md 原文要旨）

1. 阶段通过不冒充平台通过；公共基线（typecheck/test/dist:win）通过不替代功能场景。
2. 现代 Windows 阶段结果不能替代 Win7；历史 linz 或现代 Windows 记录不能替代最终包复验。
3. 最终验收不能复用不匹配候选证据：已有证据仅在候选、依赖、配置、环境匹配且覆盖本场景时引用。
4. 必需场景 failed / unexecuted / incomplete 时不得关闭 #131、不得宣称 Win7 完整兼容交付、
   不得停止 linz 有限维护或归档。
5. 用户及维护者确认必须来自本人；确认人与日期记录在案后方可翻对应条件的状态。
