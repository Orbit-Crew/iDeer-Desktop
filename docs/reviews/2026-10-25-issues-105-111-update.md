## 当前仍存在的 Server 缺口

### P1：更新路由没有接入正式 Gateway，公共入口也没有对应转发

完整读取本次候选的 [app.py](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/backend/app/gateway/app.py)，没有导入 updates，也没有 `app.include_router(updates.router)`。新增路由文件不会自动生效。

新测试 [test_updates_address.py:17](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/backend/tests/integration/api/test_updates_address.py#L17) 自行创建 FastAPI 小应用并手动挂载 updates.router，因此测试通过无法证明生产 create_app 注册了接口。

[Nginx:305](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/docker/nginx/nginx.conf#L305) 仍将 `/updates/...` 交给 frontend，未增加该路径的 Gateway 转发或静态托管；[frontend/next.config.js](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/frontend/next.config.js) 也没有 `/updates` rewrite。

应同时注册 Gateway 路由、接通公共 origin 的转发，并通过正式 create_app 和真实公共入口核对四个文件的响应及签名。该缺口同时阻断 #107 和 #110 的实际声明获取。

### P1：#105 的 grant 只做请求字段自洽检查，没有验证真实任务和当前设备

[desktop_artifacts.py:130](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/backend/app/gateway/routers/desktop_artifacts.py#L130) 只比较客户端提供的 grant.task_id/run_id/thread_id/name 是否与同一请求的字段相等。grant.token 仅有字符串长度限制，[第 170 行](https://github.com/Orbit-Crew/iDeer/blob/591f80cf3579fcd3ec527d79fa9a867f6f4fc32d/backend/app/gateway/routers/desktop_artifacts.py#L170) 保存其 hash，没有验证或消费服务端已知 grant，也没有查询 task/run 的实际归属、设备状态或撤销状态。

现有装饰器会检查登录用户、threads:write 和 Thread 所有权，应保留这项已经实现的防护。但对于仍持有效业务登录的 Thread 所有者，请求可以自行填写不存在的 run/task 和任意满足长度的 token；新接口没有再验证这些执行事实。设备撤销不会自动撤销业务账号登录，单凭 Thread 所有权不能证明原设备仍有上传资格。这不满足 #105 对设备撤销、错误归属和上传授权的要求。

应复用可验证的授权依据，将原任务、当前用户及设备绑定到实际执行记录，并补齐撤销、伪造 run/task、token 复用及正确重试的测试。本次为完整处理函数及装饰器源码判断，没有运行真实撤销请求。
